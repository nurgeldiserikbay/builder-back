# BuildPath на Render (бесплатная тестовая среда)

Тестовая среда на бесплатных планах Render и Neon. Для production по-прежнему рассчитан один сервер с Docker ([../README.md](../README.md)).

## Что запущено

| Сервис Render | Откуда | Зачем |
|---|---|---|
| `buildpath-api` | этот репозиторий, `Dockerfile` (target `app`) | API; при старте применяет миграции |
| `buildpath-front` | `builder-front`, `Dockerfile` | приложение |
| `buildpath-admin` | `builder-admin`, `Dockerfile` | консоль сотрудников |
| `buildpath-app` | этот репозиторий, `deploy/render/Dockerfile` | вход для пользователей: `/api/*` → API, остальное → приложение |
| `buildpath-console` | то же | вход для сотрудников: `/api/*` → API, остальное → консоль |

База — бесплатный проект Neon (Франкфурт). Все сервисы — регион Frankfurt, план Free.

Пользователи открывают только `buildpath-app` и `buildpath-console`: приложение и API работают на одном адресе, поэтому cookie остаются первичными и CORS не нужен. Бесплатные сервисы Render не принимают трафик по внутренней сети, поэтому вход ходит к остальным по публичным адресам `https://*.onrender.com`.

## Настройки входа (`deploy/render/Dockerfile`)

| Переменная | Пример |
|---|---|
| `API_UPSTREAM` | `https://buildpath-api.onrender.com` |
| `WEB_UPSTREAM` | `https://buildpath-front.onrender.com` или `https://buildpath-admin.onrender.com` |
| `FRAME_POLICY` | приложение: `frame-ancestors 'self' https://web.telegram.org https://*.telegram.org`; консоль: по умолчанию `frame-ancestors 'none'` |
| `NOINDEX` | `true` для консоли |

## Настройки API

Как в `../.env.production.example`, со следующими отличиями:

- `DATABASE_URL` — строка подключения Neon (`?sslmode=require`).
- `PUBLIC_APP_URL` — адрес `buildpath-app`.
- Команда запуска: `npm run start:migrate` — миграции, затем API (на бесплатном плане нет pre-deploy команды).
- Почта: без своего домена Resend отправляет только на адрес владельца аккаунта Resend, поэтому в тестовой среде используется Brevo (`BREVO_API_KEY`, `EMAIL_FROM` — подтверждённый в Brevo адрес Gmail). Такие письма чаще попадают в спам.
- `CLAMAV_HOST` не задан — загрузка фото отклоняется («Проверка файлов сейчас недоступна»). Варианты — в разделе «Проверка загрузок на вирусы».

## Ограничения бесплатной среды

- Сервис засыпает после 15 минут без запросов; первое открытие после этого занимает до минуты (просыпаются вход, приложение и API).
- На рабочее пространство даётся 750 часов работы бесплатных сервисов в месяц; спящий сервис их не тратит.
- Опубликованные сайты (`*.sites.<домен>`) не работают: для них нужен свой домен с wildcard-записью и сервер сайтов.
- Тестовая оплата (`PAYMENTS_PROVIDER=mock`) в `NODE_ENV=production` выключена.
- Адрес клиента для лимитов определяется приблизительно: запрос проходит через два прокси Render.
- Данные хранятся во Франкфурте; для пользователей из Казахстана это расходится с требованием хранить данные в РК — только для тестов.
- Фоновые задачи API (проверка опубликованных сайтов, напоминания по спорам и изменениям, недельный отчёт) работают по таймеру внутри процесса — пока API спит, они не выполняются и догоняют после пробуждения.

## Внешний монитор

Проверяет платформу снаружи и пишет, если она недоступна. Подходит бесплатный план UptimeRobot (разрешено коммерческое использование; проверка раз в 5 минут) — или Better Stack, HetrixTools.

| Что проверять | Адрес | Условие |
|---|---|---|
| API и база | `https://<buildpath-api>/api/v1/health/ready` | HTTP 200 и в ответе есть `"ready"` |
| Вход пользователей | `https://<buildpath-app>/__gateway/health` | HTTP 200, ответ `ok` |
| Приложение целиком (реже) | `https://<buildpath-app>/` | HTTP 200 |

Настройка в UptimeRobot: New monitor → тип **Keyword** → адрес из таблицы → keyword `ready` (или `ok`), «alert when keyword not exists» → интервал → контакты (почта, Telegram). `/health` без `ready` отвечает, даже если база недоступна, поэтому для монитора нужен `/health/ready`.

**На бесплатном плане Render монитор мешает.** Каждая проверка будит сервис, а не спящий сервис тратит общие 750 часов в месяц. Проверка каждые 5 минут держит сервис включённым круглосуточно (~730 часов), поэтому уже два таких сервиса исчерпают лимит в середине месяца, и Render приостановит все бесплатные сервисы. Проверка реже 15 минут ловит только «холодный старт» до минуты и даёт ложные тревоги. `/health/ready` также будит базу Neon.

Поэтому:

- пока всё на Free — монитор не включать или проверять только `buildpath-api` раз в 30–60 минут с таймаутом 60 секунд, понимая, что это проверка «просыпается ли», а не доступности;
- для постоянного монитора и работающих фоновых задач перевести `buildpath-api` на Starter ($7/мес., не засыпает, часы Free не тратит) и проверять его напрямую раз в 5 минут. Вход и приложение могут оставаться на Free — они просыпаются при первом открытии.

## Проверка загрузок на вирусы

Загрузки (скриншоты в спорах, фото портфолио) проходят через ClamAV (`src/security/clamav.ts`, протокол clamd по TCP). Без сканера в production загрузка отклоняется — это намеренно (fail-closed).

| Вариант | Стоимость | Комментарий |
|---|---|---|
| ClamAV как private service Render | от $25/мес. (Standard, 2 ГБ) | Базе сигнатур нужно ~1,6 ГБ памяти, при обновлении — вдвое больше, если не выключить `ConcurrentDatabaseReload`; официальная рекомендация — от 3 ГБ. Starter (512 МБ) не хватит. Бесплатных private service нет, а бесплатные сервисы не принимают внутренний трафик |
| ClamAV на отдельной VM с 4 ГБ | цена VM у выбранного провайдера | Открыть порт 3310 только для API (firewall + TLS-туннель или WireGuard): clamd не шифрует трафик и не проверяет клиента |
| Облачный API проверки файлов | бесплатные лимиты есть, но небольшие | Файлы пользователей уходят третьей стороне — нужно отразить в политике конфиденциальности и договоре обработки; потребует нового адаптера |
| Оставить выключенным | 0 | Для тестовой среды: функции с загрузкой недоступны, остальное работает. `UPLOAD_MALWARE_SCAN=disabled` в production не принимается |

Для тестовой среды рекомендуется последний вариант; для production — ClamAV на том же сервере, что и остальная платформа (см. `../README.md`), где памяти хватает.
